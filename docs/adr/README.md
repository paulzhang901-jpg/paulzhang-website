# Architecture Decision Records

ADRs preserve decisions that materially constrain architecture. Status values: **Proposed, Accepted, Superseded, Deprecated, Rejected**.

## Process

Create an ADR before implementing an architecture change. Accepted ADRs are immutable historical records; supersede rather than rewrite their decision. Update related docs, registries, schemas, and tests in the same review.

## Template

```markdown
# ADR-NNNN — Title
Status: Proposed
Date: YYYY-MM-DD

## Context
## Decision
## Alternatives Considered
## Consequences
## Implementation Notes
## Supersedes
None.
## Superseded By
None.
```
